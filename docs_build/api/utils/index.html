    Logging¶

    reaper.utils.logger.setup_logging ¶

    setup_logging(
    level: str | int = "INFO",
    use_color: bool | None = None,
    log_file: str | None = None,
    propagate: bool = False,
) -> None

    Configura el logging del proyecto completo.

    Debe llamarse una sola vez al inicio del programa, antes de cualquier llamada a get_logger o uso de loggers del proyecto. Configura el logger raíz "reaper" con los handlers apropiados.

    Parameters:

    Name Type Description Default
    level str | int

    Nivel de log como string ("DEBUG", "INFO", etc.) o como constante logging.*. Default: "INFO".

    		 'INFO'
    use_color bool | None

    Si True, activa colores ANSI en el handler de consola. Si None (default), autodetecta según sys.stderr.isatty().

    		 None
    log_file str | None

    Ruta opcional a un fichero de log adicional. El fichero usa siempre el formato plano (sin color) y nivel DEBUG.

    		 None
    propagate bool

    Si True, los mensajes se propagan también al logger raíz de Python (útil para frameworks que configuran el root). Default: False — Reaper gestiona sus propios handlers.

    		 False

    Example::

    # CLI normal
setup_logging(level="INFO")

# Sesión de depuración
setup_logging(level="DEBUG", use_color=True)

# Producción con fichero de log
setup_logging(level="WARNING", log_file="/var/log/reaper.log")

    reaper.utils.logger.get_logger ¶

    get_logger(name: str) -> logging.Logger

    Devuelve el logger para el módulo indicado.

    Wrapper mínimo sobre logging.getLogger(name) que actúa como punto de importación único para todos los módulos del proyecto. No añade configuración propia — el logger hereda la configuración establecida por setup_logging a través de la jerarquía "reaper.*".

    Parameters:

    Name Type Description Default
    name str

    Nombre del módulo. Usar siempre __name__ para preservar la jerarquía automática de loggers.

    		 required

    Returns:

    Type Description
    Logger

    Logger configurado para el módulo.

    Example::

    # En cualquier módulo del proyecto:
from reaper.utils.logger import get_logger
logger = get_logger(__name__)

    reaper.utils.platforms.detect_platform_from_url ¶

    detect_platform_from_url(url: str) -> str

    Detecta la plataforma de redes sociales a partir de la URL.

    Extrae el netloc de la URL y lo compara contra el catálogo de dominios PLATFORM_DOMAINS. La comparación usa netloc == dominio o netloc.endswith('.' + dominio), lo que evita falsos positivos por substring (p. ej. "t.co" no coincide con "snapchat.com").

    Parameters:

    Name Type Description Default
    url str

    URL completa o parcial con dominio. Se acepta con o sin protocolo.

    		 required

    Returns:

    Type Description
    str

    Identificador de la plataforma en minúsculas (ej. "facebook",
    str

    "youtube", "x"), o "unknown" si el dominio no coincide
    str

    con ninguna entrada del catálogo.

    Examples:

    >>> detect_platform_from_url("https://www.facebook.com/reel/12345")
'facebook'
>>> detect_platform_from_url("https://youtu.be/dQw4w9WgXcQ")
'youtube'
>>> detect_platform_from_url("https://twitter.com/user/status/123")
'x'
>>> detect_platform_from_url("https://t.co/abc123")
'x'
>>> detect_platform_from_url("https://vm.tiktok.com/abc123/")
'tiktok'
>>> detect_platform_from_url("https://t.me/channel/123")
'telegram'
>>> detect_platform_from_url("https://wa.me/+34612345678")
'whatsapp'
>>> detect_platform_from_url("https://www.snapchat.com/add/user")
'snapchat'
>>> detect_platform_from_url("https://bsky.app/profile/user")
'bluesky'
>>> detect_platform_from_url("https://discord.gg/abc123")
'discord'
>>> detect_platform_from_url("https://www.google.com")
'unknown'
>>> detect_platform_from_url("")
'unknown'

    Detector de autenticación¶

    reaper.utils.fb_auth_detector.requires_auth ¶

    requires_auth(
    html_content: str, final_url: str = ""
) -> AuthResult

    Detecta si el HTML de Facebook o Instagram indica que se requiere autenticación.

    Analiza el HTML en capas ordenadas de más específica a más general. El orden es crítico: capas más específicas deben ejecutarse primero para evitar que señales generales produzcan falsos negativos.

    1. Contenido explícitamente no disponible — dos niveles de señales:
     · JSON (ScheduledServerJS, HTML SSR): canonicalRouteName, tracePolicy
     · DOM (post-hidratación): <title>, <span> con texto de error
2. Presencia de señales de contenido real (early exit: NO bloqueado)
3. URL final redirigida a /login, /checkpoint (FB) o /accounts/login (IG)
4. Señales JSON fuertes (tracePolicy, canonicalRouteName) — solo Facebook
5. Señales JSON combinadas (CometErrorRoot + privacy) — solo Facebook

    Parameters:

    Name Type Description Default
    html_content str

    HTML renderizado por Playwright (SSR o post-hidratación).

    		 required
    final_url str

    URL final tras redirecciones HTTP.

    		 ''

    Returns:

    Type Description
    AuthResult

    class:AuthResult: - requires_auth=False + auth_type="content_unavailable" si el contenido fue eliminado o restringido permanentemente (FB e IG). - requires_auth=False sin auth_type si la página tiene contenido real. - requires_auth=True con auth_type correspondiente si hay muro de auth.

    Métricas¶

    reaper.utils.metrics.SocialMediaParser ¶

    SocialMediaParser()

    Parser de métricas de redes sociales con soporte de sufijos K, M y B.

    Convierte representaciones textuales de cantidades (como "5.2K", "1.5M", "2,300") a valores enteros. Diseñado para parsear los valores de engagement que aparecen en el HTML o tráfico JSON de plataformas como Facebook o Instagram.

    Los resultados se acumulan en self.result y también se devuelven como valor de retorno de cada método, lo que permite encadenar llamadas o usar la instancia como acumulador.

    Attributes:

    Name Type Description
    result dict[str, int]

    Diccionario acumulativo con todos los campos parseados. Se rellena en cada llamada a _parse_metric o parse_engagement_metrics.

    Examples:

    >>> parser = SocialMediaParser()
>>> parser._parse_metric("5.2K", "likes")
5200
>>> parser._parse_metric("1.5M", "shares")
1500000
>>> parser.result
{'likes': 5200, 'shares': 1500000}

    Inicializa el parser con un acumulador de resultados vacío.

    parse_engagement_metrics ¶

    parse_engagement_metrics(
    reaction_count: str | int | float | None,
    share_count: str | int | float | None,
    comment_count: str | int | float | None = None,
) -> dict[str, int]

    Parsea las métricas principales de engagement en una sola llamada.

    Parsea reacciones, compartidos y opcionalmente comentarios, y los almacena en self.result. Es el método de conveniencia habitual para extraer métricas del tráfico de redes sociales.

    Parameters:

    Name Type Description Default
    reaction_count str | int | float | None

    Total de reacciones (likes, loves, etc.).

    		 required
    share_count str | int | float | None

    Total de veces que se compartió el contenido.

    		 required
    comment_count str | int | float | None

    Total de comentarios. Si es None, no se añade comment_count al resultado.

    		 None

    Returns:

    Type Description
    dict[str, int]

    Diccionario con las métricas parseadas. Siempre contiene
    dict[str, int]

    reaction_count y share_count. Contiene comment_count
    dict[str, int]

    solo si se proporcionó un valor distinto de None.

    Examples:

    >>> parser = SocialMediaParser()
>>> parser.parse_engagement_metrics("5.2K", "342", 89)
{'reaction_count': 5200, 'share_count': 342, 'comment_count': 89}

    >>> parser2 = SocialMediaParser()
>>> parser2.parse_engagement_metrics("1.1M", None)
{'reaction_count': 1100000, 'share_count': 0}

    datetime_encoder(obj: Any) -> str

    Encoder personalizado para serialización JSON de objetos datetime.

    Usar como argumento default en json.dump / json.dumps cuando el diccionario a serializar contiene campos de tipo datetime.

    Parameters:

    Name Type Description Default
    obj Any

    Objeto a serializar. Si es datetime, se convierte a ISO 8601. Para cualquier otro tipo no serializable natively por JSON, se lanza TypeError.

    		 required

    Returns:

    Type Description
    str

    Representación ISO 8601 del datetime (ej. "2024-01-15T14:30:00").

    Raises:

    Type Description
    TypeError

    Si el objeto no es de tipo datetime.

    Examples:

    >>> import json
>>> from datetime import datetime
>>> from utils.encoding import datetime_encoder
>>> data = {"ts": datetime(2024, 1, 15, 14, 30)}
>>> json.dumps(data, default=datetime_encoder)
'{"ts": "2024-01-15T14:30:00"}'

    reaper.utils.encoding.decode_alphanumeric_id ¶

    decode_alphanumeric_id(b64_id: str) -> str | None

    Decodifica un feedback_id de Facebook en base64 para obtener el ID numérico.

    Facebook codifica algunos IDs de feedback y comentarios en base64 con el formato "feedback:<post_id>" o "comment:<comment_id>". Este método extrae la parte numérica tras los dos puntos.

    Parameters:

    Name Type Description Default
    b64_id str

    ID alfanumérico en base64 tal como aparece en el HTML o tráfico GraphQL (ej. "ZmVlZGJhY2s6MTIzNDU2Nzg5MDEyMzQ1")

    		 required

    Returns:

    Type Description
    str | None

    El ID numérico como string si la decodificación es exitosa, o None
    str | None

    si el formato es inválido, la entrada está vacía o la decodificación falla.

    Examples:

    >>> decode_alphanumeric_id("ZmVlZGJhY2s6MTIzNDU2")
'123456'
>>> decode_alphanumeric_id("")
None
>>> decode_alphanumeric_id("no_es_base64!!!")
None
